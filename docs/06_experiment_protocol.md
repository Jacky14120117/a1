# 无监督实验与评价协议

协议版本：v1。核心数值写在 `configs/project.yaml`。这是一份在聚类执行前固定的比较规则，用来避免根据好看的簇反向改口径。方案变化应保留旧运行并说明原因。

## 1. 研究对象与表示

主样本：同一站点六污染物各自至少 18 个有效小时的日。原始版本预计 n=1,333。主矩阵列顺序为 PM2.5、PM10、SO2、NO2、CO、O3，原始单位均 µg/m³。

主表示为 `Z_j = (log(1+x_j)-mean_j)/std_j`，采用 StandardScaler 的总体标准差口径。数值 x 以原始单位记录，log1p 的 1 对应该数值单位中的 1。没有监督标签，不使用日期、季节、气象或站点参与距离。PCA 不进入主模型。

本研究对已观测数据做探索性聚类，可以在全主样本上拟合主缩放器。不进行随机 80/20 预测划分。稳定性子样本重新拟合各自缩放器，以衡量整个流程对数据扰动的敏感性。

## 2. 候选实验

| 编号 | 方法 | 参数与固定项 | 候选结果数量 |
| --- | --- | --- | ---: |
| E01 | K-Means | k=2…8；seed=100…109；n_init=20；max_iter=300；Lloyd | 70 |
| E02 | Ward | 同一 Z，Euclidean；一棵树切 k=2…8 | 7 |
| E03 | DBSCAN | m=5/10/20；每个 m 的 k-distance 分位数 0.70/0.80/0.90/0.95 | 12 |
| E04 | 主方法划分比较 | 各代表结果，以及同 k 的七组对照 | 至少 8 组比较 |
| E05 | 时间块稳定性 | 每个入围主候选 20 次；密度代表有效时另 20 次 | 随入围数量记录 |
| E06 | 变换敏感性 | raw+StandardScaler，主代表各自固定 k | 2 |

Ward 只拟合一棵树再得到七个结果，不能把七次切分说成七种独立算法。所有候选均保留，失败记录也进入结果表。

### DBSCAN 的 eps 生成

对每个 min_samples=m，调用 `NearestNeighbors(n_neighbors=m).fit(Z).kneighbors(Z)`，显式把 Z 作为查询，因此邻域包含查询样本本身；取距离数组第 m-1 列。该口径与 DBSCAN 的 min_samples 包含自身一致。

采用 NumPy 分位数 `method='linear'`。将四个分位数得到的 eps 原值保存到表中，再拟合 `DBSCAN(eps=...,min_samples=m,metric='euclidean')`。若 eps=0，记 `invalid_eps`，不得悄悄改为极小正数；若同 m 多个分位数产生相同 eps，可复用一次拟合，但 12 个设置仍各有记录并注明重复。主方法结果不因此改变。

## 3. 指标与有效性

| 指标 | 目的与方向 | 注意 |
| --- | --- | --- |
| Silhouette | 簇内紧密和簇间分离，越大越好 | 需 2<=簇数<=样本数-1；欧氏紧凑簇偏好 |
| Davies–Bouldin | 簇间相似程度，越小越好 | 与 silhouette 不是独立科学真值 |
| Calinski–Harabasz | 簇间/簇内散度比，越大越好 | 随样本与 k 改变，需同数据同空间比较 |
| Inertia | K-Means 的簇内平方和 | 只用于 K-Means 肘部观察，不跨算法排名 |
| ARI | 不同划分的一致性，1 为一致，接近 0 表示接近随机参照 | 可为负；不需要类别真值，对编号置换不敏感 |
| n、簇大小、覆盖率、噪声率 | 表示实际划分范围 | DBSCAN 与其他方法比较时不可省略 |

K-Means 与 Ward 的内部指标在同一六维 Z 和全部 n 上计算。n 约 1,333 时可以使用全部样本，不必随机抽小样本来追求更高分数。所有指标保存足够精度，展示时再格式化。

DBSCAN 先去掉 -1，仅在非噪声子集满足有效标签数时计算三项内部指标。`coverage=n_assigned/n`，`noise_fraction=n_noise/n`，`n_clusters` 不含 -1。单簇加噪声仍是一个簇，其 silhouette 为 null。全噪声同理。内部指标的 n_scored 必须单列。

指标无效、异常或非有限时，保存 null 与 `metric_reason`，不保存 0，不静默删掉候选。DBSCAN 的子集 silhouette 与全样本 K-Means/Ward silhouette 的统计对象不同，禁止不加限定地将三者排序得出算法优劣。

## 4. 主方法代表 k 的选择

不提前规定最后的簇数，也不需要两种方法选出相同 k。

1. 排除退化设置。代表候选的每个簇至少 `max(10,ceil(0.01*n))` 日。当前 n=1,333 时为 14 日。该阈值是可解释性的项目规则，过小簇仍保留在候选表中。
2. K-Means 按每个 k 的十种子 silhouette 中位数汇总，主画像和簇大小检查固定使用 seed=100。Ward 使用其唯一切分分数。任何收敛警告须单独披露。
3. 在各方法内部取 silhouette 与本方法合格候选最佳值相差 <=0.02 的 k 组成入围集合。DB/CH 与肘部/树状图用于解释，不反向加权制造新总分。
4. 对每个入围 k 做第 6 节的 20 次稳定性；以中位 ARI 最大者为代表。若多个中位 ARI 距最大值 <=0.02，优先更小 k，再按更高 silhouette、数值 k 升序打破剩余并列。
5. 若所有候选都不满足最小簇规则，不强制选代表。保留真实结果，标记“无合格代表”，讨论小簇/连续结构并记录任何后续协议修订。
6. 若代表的时间块中位 ARI<0.70，标记稳定性偏弱。0.70 是本项目警示线，不是领域公认的有效性证明。

保存 `selection.json`：所有入围项、排除原因、选择所用值、最终代表及协议版本。此后再看季节和天气解释图，不能以“冬季看起来更整齐”改选 k。

不要求指定一个跨方法胜者。最终可以推荐一个更易解释的代表划分供展示，同时保留另一方法的结构和分歧；推荐依据必须同时讨论紧密性、稳定性、分辨率与解释范围。

## 5. DBSCAN 代表设置

先要求至少两个非噪声簇、每簇至少主分析相同的最小日数、coverage>=0.70 和有效内部指标。按非噪声 silhouette 最大值形成差值 <=0.02 的集合，在其中优先覆盖率更高者，再按 m 升序、eps 升序打破并列。该规则只用于 DBSCAN 内部选展示设置。

如果没有合格项，完整报告参数敏感性及退化情况即可。DBSCAN 作为补充，不影响两种主方法满足课程比较要求。不得因为没有合适密度簇就把 -1 作为第二个真实簇。

## 6. 稳定性口径

### 初始化稳定性

每个 k 的 K-Means 十个种子结果两两计算 45 个 ARI，报告中位数、IQR、最小值；同时保留每个种子的指标。它衡量算法初始化敏感性，不衡量抽样或未来泛化。

### 时间块子采样

以完整 1,461 日日历定义 `block_id=floor((date-2013-03-01).days/7)`，共 209 个块，最后一块可不足七日。每次用独立 `np.random.default_rng(seed)` 无放回选 floor(0.8×209)=167 块，种子 100…119，取所选块内的合格日。因为缺失分布不同，合格日保留比例不必正好为 80%。保存每次块 ID 和实际日期。

在每个子集重新拟合缩放和当前候选聚类，并将子集标签与完整参考标签限制到相同日期后计算 ARI。Ward 可为每个子集拟合一棵树供多个入围 k 复用。所有方法使用相同子样本日期；全量参考主标签固定 seed=100。

报告 20 个 ARI、中位数、Q1/Q3及有效重复数。若子集无法形成有效划分，记原因且不得在汇总中掩盖失败次数。该数值不是置信区间，也不是独立验证性能。选择 k 使用了这些稳定性结果，应明确说明探索性选择偏差。

### DBSCAN 稳定性

固定主分析选定的实际 eps 和 m。比较时去掉全量或子集任一结果为 -1 的共同日期，仅在双方均至少两个非噪声簇时报告 ARI，并给共同有效日期占子样本的比例。

另报告噪声集合 Jaccard：共同日期内两个噪声集合交集大小/并集大小；并集为空时记 null 和 `no_noise_in_both`，不误写为发现稳定异常。大量噪声点一致不能冒充污染簇稳定。

## 7. 方法差异分析

对主代表使用 ARI 与列联表，不按簇编号直接相等比较。另在 k=2…8 各给一组同 k 的 K-Means(seed=100) 与 Ward ARI，避免把簇数差异全归因于算法。

所有比例都标明分母。簇画像在原始单位上直接从日表按实际标签分组计算中位数与 IQR，不能把 log 空间中心反变换后称为算术平均。若为了显示重排簇号，保留原始标签与显示编号映射，ARI 使用原始或等价置换均可。

DBSCAN 的交叉方法 ARI 如需展示，只在明确的共同非噪声日期上计算并报告覆盖率；不与全量主方法 ARI 混为同口径。

## 8. 敏感性与知识解释

必做分支：同一主日表用原始值 StandardScaler，固定各主方法已选 k。报告与主表示的 ARI、簇大小和原始浓度画像变化，不跨表示宣称某 silhouette 更高便是真实模式更好。

季节、年份、天气在主设置冻结后进入解释。先比较“同簇内的浓度差异”，再讨论气象背景或季节分布。季节百分比有实际合格日分母；缺失集中月份单独说明。天气关联不能证明因果，簇不等于污染源或官方健康等级。

不把由六污染物自身形成的簇，再对这六列做显著性检验后宣称独立验证了发现。若做天气的探索性统计，也需考虑时间依赖、多重比较和混杂；本项目核心采用描述性分析即可。

## 9. 运行与结果契约

运行 ID 建议为 UTC 时间戳 + 配置哈希前八位，目录 `results/runs/<run_id>/`。保存配置、协议版本、数据哈希、实际依赖、代码哈希、日期与特征顺序、所有候选设置、错误/警告、耗时。未提交代码时保存参与运行源码的 SHA256 清单，不能仅记录 Git HEAD 后声称包含未提交改动。

`experiments.csv` 至少包含 run_id、experiment_id、algorithm、k/eps/min_samples、seed、representation、n_total、n_scored、n_clusters、noise_fraction、min_cluster_size、silhouette、DB、CH、inertia、runtime_seconds、status、metric_reason。标签用 date 键存长表或逐设置 CSV，不能只保存没有日期的数组。

软件浮点误差采用适当容差。簇号任意置换不算复现失败，可用 ARI=1 及相同指标确认等价划分。
